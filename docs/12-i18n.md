# 12 — i18n do painel

**Lib:** [next-intl](https://next-intl.dev) v4 · **Idiomas:** `pt` (padrão), `es`, `en` ·
**Roteamento:** sem prefixo de locale — as URLs continuam `/users`, `/accounts` etc.
(`localePrefix: 'never'`).

---

## 1. Como o locale é resolvido

Em ordem de prioridade:

1. **`admin_users.locale`** do usuário logado — aplicado em
   `apps/panel/src/app/(app)/layout.tsx` via `setRequestLocale(me.locale)` +
   `<NextIntlClientProvider locale={me.locale}>`.
2. **Cookie `NEXT_LOCALE`** — usado nas telas `/login/*` (sem sessão ainda) e como
   fallback caso o passo 1 não se aplique.
3. **`Accept-Language`** do navegador, na primeira visita.
4. **`PANEL_DEFAULT_LOCALE`** (env, default `pt`) — piso de todo o resto.

`apps/panel/src/i18n/request.ts` resolve só os passos 2-4 (nunca acessa o banco —
roda também no prerender do build). O passo 1 é aplicado por cima, no layout
autenticado, porque é o único lugar com a sessão já carregada.

`loginAction` e `setupTotpAction` (`apps/panel/src/app/actions/auth.ts`) gravam o
cookie `NEXT_LOCALE` com o locale do usuário logo após autenticar — assim as
server actions seguintes (que não têm layout, só o cookie) já ficam no idioma certo.

## 2. Arquivos de mensagem

`apps/panel/messages/{pt,es,en}.json` — um arquivo por locale, mesmas chaves
(namespaced por área: `nav`, `dashboard`, `accounts`, `messages`, `chat`, `queue`,
`projects`, `settings`, `users`, `alerts`, `login`, `setup`, `actions.*`, `enums.*`,
`disconnectReason`, `ssrfReason`, `sendError`, `stream`, `common`, `metadata`).

**`pt.json` é a referência.** `es.json`/`en.json` precisam ter exatamente o mesmo
conjunto de chaves — verificado por:

```bash
node scripts/check-messages.mjs
```

Roda no CI antes do build do painel; falha (exit 1) se algum arquivo tiver chave
faltando ou sobrando.

### Como adicionar um idioma novo

1. `packages/config/src/env.ts` — adicionar o código ao enum `PANEL_DEFAULT_LOCALE`.
2. `apps/panel/src/i18n/routing.ts` — adicionar aos arrays `locales`, `htmlLang`,
   `localeNames`.
3. Criar `apps/panel/messages/<novo>.json` com todas as chaves de `pt.json`.
4. `packages/email/src/email-templates.ts` — adicionar uma entrada em `RESET_COPY`
   e `INVITE_COPY`.
5. `node scripts/check-messages.mjs` — confirmar paridade.

Nenhuma migration de banco é necessária (a coluna `locale` é `String` livre,
validada no código, não um enum do Postgres).

## 3. Formatação de data/número

`apps/panel/src/i18n/request.ts` define os formatos nomeados usados em toda a
aplicação:

| Nome | Uso |
|---|---|
| `dateTime.short` | timestamp completo em tabelas (`format.dateTime(d, 'short')`) |
| `dateTime.date` | só a data |
| `dateTime.time` | só a hora |
| `number.percent` | taxas (1 casa decimal) |

Server Components usam `getFormatter()` de `next-intl/server`; Client Components,
`useFormatter()` de `next-intl`.

## 4. Rótulos de enum/token

Nada no domínio (`@wpp/shared/enums.ts`, `disconnect.ts`, `ssrf.ts`, códigos de
erro de envio) carrega um rótulo legível — são tokens estáveis
(`AccountStatus.CONNECTED`, `loggedOut`, `invalid_url`, `RATE_LIMITED`, …).

`apps/panel/src/i18n/labels.ts` mapeia token → chave de mensagem, com fallback pro
próprio token se a chave não existir (`t.has(key)`):

```ts
accountStatusLabel(t, 'CONNECTED')      // → t('enums.AccountStatus.CONNECTED')
messageStatusLabel(t, 'DELIVERED')      // → t('enums.MessageStatus.DELIVERED')
disconnectReasonLabel(t, 'badSession')  // → t('disconnectReason.badSession')
sendErrorLabel(t, 'RATE_LIMITED')       // → t('sendError.RATE_LIMITED')
```

⚠️ **`ssrfReasonLabel`** é diferente dos demais: espera um translator **já
namespaced** em `ssrfReason` (`await getTranslations('ssrfReason')`), porque o
token de SSRF é interpolado dentro de uma frase de outro namespace
(`actions.projects.webhookUrlInvalid`). Os outros helpers esperam o translator
**raiz** (`await getTranslations()`, sem argumento) porque prefixam o caminho
completo (`enums.AccountStatus.*`).

Ao adicionar um token novo em `@wpp/shared`, adicionar a chave correspondente nos
3 arquivos de mensagem — senão o rótulo cai no fallback (token cru), que é seguro
mas feio.

## 5. E-mails (`@wpp/email`)

`resetPasswordEmail` e `inviteEmail` (`packages/email/src/email-templates.ts`)
recebem um `locale` opcional (default `'pt'`). A cópia de cada idioma vive numa
tabela `Record<'pt'|'es'|'en', {...}>` **dentro do próprio arquivo** — sem
dependência de next-intl, porque o pacote também é consumido pelo worker
(alertas, que continuam em um idioma fixo, fora de escopo do i18n de usuário).

- `requestPasswordResetAction` usa `user.locale` (o destinatário do reset).
- `inviteUserAction`/`resendInviteAction` usam `me.locale` (quem convida) — o
  convidado ainda não tem preferência própria; herda a de quem convidou
  (`createInvitedAdmin({ locale: me.locale })`).

---

## 6. O que fica fora do escopo do i18n de usuário

- **Alertas do worker** (`apps/worker/src/alerts/channels.ts`) — vão para um
  endereço fixo de operação, não um usuário específico; idioma único (poderia
  usar `PANEL_DEFAULT_LOCALE` no futuro, não implementado).
- **Erros 500 inesperados** (exceções não previstas) — mantêm a mensagem original
  em vez de cada `catch` traduzir todo caminho possível.

---

## 7. Checklist de QA manual

O painel não tem harness de teste de UI — validar manualmente após qualquer
mudança de i18n:

- [ ] Sem cookie → painel abre em `PANEL_DEFAULT_LOCALE`.
- [ ] `Accept-Language: es` → `/login` em espanhol; cookie `NEXT_LOCALE` gravado.
- [ ] Login com usuário `locale='en'` → todas as telas `(app)` em inglês,
      `<html lang="en">`, datas e rótulos de enum em inglês.
- [ ] Seletor de idioma no painel → grava DB + cookie, re-renderiza, persiste após
      logout/login.
- [ ] Seletor de idioma no login → só cookie; forgot/reset/setup seguem.
- [ ] Cada caminho de erro/ok das server actions, nos 3 locales.
- [ ] "Esqueci a senha" → e-mail no locale do usuário-alvo.
- [ ] Convite → e-mail no locale de quem convida; 1º login do convidado já nesse idioma.
- [ ] QR stream + chat stream conectam normalmente.
- [ ] Dashboard "Falhas por motivo" com um código de erro desconhecido → mostra o
      código cru, não `MISSING_MESSAGE`.
